# 이 킷을 실제로 돌려서 드러난 것

킷의 규칙은 대부분 여기 적힌 사고에서 나왔다. **규칙만 읽고 근거를 잃으면 규칙이
취향처럼 보이고, 취향은 다음 사람이 지운다.** 그래서 근거를 따로 둔다.

새 항목은 **겪은 그 자리에서** 적는다. 미결 항목은 여기 적지 말고 이슈로 만든다
(`CLAUDE.md` 참조).

## 실전에서 드러난 것 (읽어서는 안 나오는 것들)

**스킬 6개 중 5개가 첫 사용에서 버그였다.** 전부 *써야만* 드러났다:

| | 버그 |
| --- | --- |
| `open-pr` | 게이트 경로가 vendor 레이아웃과 불일치 |
| `devlog` | "최신이 위" 가정 — 프로젝트는 반대 순서 |
| `devlog` | 코멘트 없는 PR 에서 PR 맥락이 통째로 사라짐(jq 빈 배열 함정) |
| `trace` | `git diff main...HEAD` 만 봐서 **미커밋·untracked 변경이 안 보임** — 추적표의 테스트 칸을 채우는 게 이 스킬의 일인데 새 테스트 파일은 거의 항상 untracked 다 |
| 권한 deny | 넓힌 패턴이 커밋 메시지 내용까지 매칭 → 정상 커밋 차단 |

`open-pr`·`devlog`·`trace` 는 같은 형태다: **스킬이 돌아가는 실제 상태를 잘못 가정했다**
(vendor 레이아웃 · 로그 순서 · git 작업트리). 새 스킬을 쓸 때
"이 명령이 내가 있는 상태에서 실제로 뭘 보는가" 를 먼저 확인하라.

**리뷰 두 층은 서로 다른 것을 잡는다** (실측 2회):

| | 1차 PR | 2차 PR |
| --- | --- | --- |
| 셀프(맥락 보유) | 3건 | 3건 |
| 콜드(맥락 없음) | **11건** | **7건** |

콜드가 크게 앞섰지만 **셀프만 잡은 것도 있다** — "PR 본문이 5개 커밋만큼 낡았다"는
맥락을 가진 쪽만 안다. 한 층으로 줄이지 마라.

**같은 결함 부류를 세 번 놓쳤다.** "검사가 고장 나면 조용히 통과" 를 `secrets.sh` 에서
막아놓고 `gate_run_empty`·`gate_skip`·coverage 잡에 그대로 남겨뒀다. 인스턴스를 고치고
부류를 안 닫는 패턴이 반복된다 — 결함을 고칠 때 **같은 형태가 어디 또 있는지 먼저 찾아라.**
(카운트에는 **발현 가능했던 것만** 넣는다. 도달 불가능한 경로를 섞으면 이 숫자가
검증 체계의 근거로 못 쓰게 된다.)

**"부류를 닫아라"에는 정지 조건이 필요하다 — R7 이 그것이다.** 위 문장만 읽고 설치
스크립트의 `cp`·`chmod` 실패까지 방어하다가, 그 경로가 **도달 불가능**함을 뒤늦게
확인하고 되돌렸다(`cp -R` 이 모드를 보존하므로 `chmod` 실패는 가짜 바이너리를 PATH 에
심어야만 재현된다). 재현에 환경 조작이 필요하면 방어가 아니라 죽은 코드다.

**훅은 실행권한 없이 커밋돼 있으면 조용히 안 돈다.** 설치 문제가 아니라 **설치 이후**
문제다 — `core.fileMode=false` 인 레포, 그리고 편집기가 훅을 지우고 다시 쓸 때 인덱스
모드가 100644 로 떨어진다(둘 다 재현). CI 는 파일 *존재*만 봤기에 통과시켰다.
CI 에 `[ -x ]` 를 넣었다. 게이트 스크립트는 훅이 `bash <경로>` 로 부르므로 권한이
필요 없다 — 거기까지 요구했다가 정상 레포에서 오탐이 나 좁혔다.

**리뷰 없이 8커밋을 밀었더니 기능이 죽어 있었다.** 2026-08-24 세션에서 킷 `main` 에
PR 없이·콜드 리뷰 없이 8커밋을 넣었고, 뒤늦게 콜드 리뷰를 돌리자 **9건**이 나왔다.
가장 나쁜 것은 `gate_go_tool` 함수가 통째로 사라진 것이었다 — 다른 함수를 슬라이스로
교체하면서 같은 구간의 무관한 함수를 같이 지웠고 호출부만 남았다. `GATE_STRICT` 기본값을
1 로 바꾼 직후라 **모든 Go 프로젝트가 커밋·푸시·CI 에서 실패**하는 상태로 올라가 있었고,
메시지는 이미 설치된 도구를 설치하라고 했다.

| | 찾은 것 |
| --- | --- |
| 작성자 자신(우연히 다시 보다) | 4건 — 전부 "덜 좋은 것" |
| 콜드 리뷰 | **9건** — 상당수가 "기능이 죽어 있음" |

같은 세션에서 커밋 린트가 **엉뚱한 파일을 검사**하고 있었던 것(범위가 `main...HEAD` 라
브랜치 두 번째 커밋부터 스테이지한 파일이 범위 밖), 충돌 마커 검사가 **한글 파일명에서
조용히 통과**하던 것(`core.quotePath` 기본값)도 콜드 리뷰가 잡았다.

> **킷이 자기 문서에 "설정·CI·훅·게이트 스크립트는 글이 아니라 코드다 — 콜드 리뷰는
> 기본으로 돈다" 고 써놓고, 그 파일들만 골라 고치면서 한 번도 안 돌렸다.**
> 그래서 이 레포도 **브랜치 → PR → 콜드 리뷰 → 머지**로 간다(PR #1 부터).
> 게이트·훅 설치 여부(열린 결정 1)와는 별개로 채택한 작업 흐름이다.

**측정하지 않은 수치로 설계를 결정하지 마라.** 같은 세션에서 "커밋에 린트를 넣으면
22초"라는 이유로 그 안을 두 번 폐기했는데, 22초는 `--all`(CI 모드)이었고 실제 커밋은
**2.8초**였다. "변경 파일만 린트하면 싸다" 도 틀렸다(eslint 은 파일 1개도 4.4초).
"npm 기동 비용이 크다" 도 틀렸다(node 기동 0.07초, eslint 자체가 4.7초).
**세 번 다 추정이었고 세 번 다 틀렸다.**

**권한 deny 는 원리적으로 신뢰할 수 없다.** Bash 권한 glob 은 플래그와 인자 내용을
구분하지 못한다. 단축 플래그(`-n`·`-f`)·결합 형태(`-an`)·장문 조합을 열거로 닫을 수 없고,
넓히면 오탐만 는다. 그래서 speed bump 로 강등하고 한계를 명시했다.
**이건 원칙 1을 강화하는 증거다** — 에이전트 안의 층은 못 믿고, 밖의 층은 믿을 수 있다.

**YAML 파싱 통과는 워크플로가 유효하다는 뜻이 아니다.** `--lang py,ts` 로 거른
`gates.yml` 이 `yaml.safe_load` 를 통과했고 잡·스텝·체크섬까지 다 맞았는데, GitHub 은
`This run likely failed because of a workflow file issue` 로 거부했다. 원인은 언어 전용
변수를 다 뺀 뒤 남은 값 없는 `env:` 였다 — YAML 로는 `env: None` 으로 멀쩡히 파싱된다.

**그 `env: None` 은 내 검증 출력에 이미 찍혀 있었다.** 잡 목록과 줄 수만 보고 지나쳤다.
출력을 냈다고 읽은 것이 아니다.

고친 뒤로는 `actionlint` 로 닫는다(스크래치패드에 받아서 쓴다). 파서가 아니라
**그 파일을 실제로 소비하는 도구**로 검증해야 이 부류가 닫힌다.

## 체크섬을 걷어낸 근거 (2026-09)

`.ai-kit/VERSION` 에 vendor 내용의 체크섬을 적고 CI 가 재계산해 대조했다. 그 층이
**킷의 다른 설계와 정면으로 부딪힌다.** `.ai-kit/README.md` 는 게이트에 문제가 있으면
그 레포에서 고치라고 말하는데, 체크섬은 그것을 CI 실패로 만든다.

설치된 데모 레포에서 실제 결함(`secrets.sh` 가 AWS secret access key 를 못 잡는 것)을
고치는 시나리오로 한 바퀴 돌렸다:

```
1) .ai-kit/gate/secrets.sh 에 패턴 추가   → 차단됨 (결함이 고쳐졌다)
2) CI 의 vendored 잡                      → ::error:: 기록 3995903652f8ff97 ≠ 실제 f595946954f16a85
3) 안내대로 install.sh 재실행             → 수정 잔존 0건. 출력에 경고 한 줄 없음
```

3번이 결정적이다. 빨간 것을 푸는 유일한 안내가 **그 수정을 말없이 지운다.**

조사해 보니 "체크섬 불일치 = CI 실패" 는 개발 도구의 관행도 아니었다. 같은 목적에
쓰는 것은 **재생성 후 diff** 다(k8s 의 `hack/verify-codegen.sh` 는 실패 메시지에
`Please run hack/update-codegen.sh` 를 담는다). 체크섬은 "달라졌다" 만 말하고 **어떻게
되돌리는지를 말하지 못한다.** 체크섬 기반 3-way 병합은 재생성이 불가능한 환경, 즉 OS
패키지 매니저(dpkg conffiles 의 md5sum, ucf 의 `diff3`)에 있다.

킷의 vendor 내용은 프로젝트 안에서 생성되는 것이 아니라 **다른 레포에서 복사돼 온 것**
이라, "재생성" 에 해당하는 동작이 곧 덮어쓰기다. 그래서 둘 중 어느 쪽도 아닌 자리에
있었다. 걷어내고, 대신 무엇이 달라졌는지를 `--dry-run` 이 보여주게 했다.

## 자동 병합을 걷어낸 근거 (2026-09)

킷을 실제 프로젝트 하나(`sera`)에 설치해 24개 PR 을 굴린 뒤, 포크 시점 킷(`a93ee25`)을
**같은 언어 선택으로 빈 레포에 재설치해** 순수 델타를 냈다. 이 단계를 건너뛰면 언어
필터가 만든 차이를 프로젝트 수정으로 오인한다 — `gates.yml` 은 그냥 비교하면 181줄이
다르지만 프로젝트가 고친 것은 19줄이다.

결과: 프로젝트가 킷 파일을 고친 **27건 중 그 프로젝트만의 사정은 2건**
(과제 PDF 를 위한 `permissions.ask`, 프로젝트 전용 CI 워크플로)이고 나머지는 전부
킷 자신의 버그였다. 그중 **셋은 킷 쪽에서도 같은 기간에 따로 고쳤다** — `집행자` →
`누가 막나` 개명, `gates.yml` 의 빈 `env:` 블록, 그리고 시크릿 범위 스캔. 마지막 것은
양쪽이 낸 코드가 **바이트 단위로 같다**:

```bash
FILES=$(git log --name-only --diff-filter=ACM --diff-merges=cc --pretty=format: "$RANGE" | sort -u | sed '/^$/d')
DIFF=$(git log -p -U0 --diff-merges=cc --pretty=format: "$RANGE")
```

3-way 병합은 "커스터마이즈와 업스트림 변경의 충돌" 을 푸는 장치인데, 실제로 치른 비용은
**같은 버그를 두 곳에서 두 번 고치는 것**이었다. 병합으로는 풀리지 않는다.

## 실증된 것

- `main` 직접 커밋 차단 · 시크릿 커밋 차단 · 깨진 코드 push 차단 — **순수 `git` 명령으로 확인**(에이전트 없이)
- 게이트가 실 2언어 모노레포에서 10개 검사, **CI 에서 건너뜀 0**(`GATE_STRICT`)
- `trace.sh` 가 누락·유령·없는 경로(구현·테스트 양쪽) 검출
- vendor 체크섬 드리프트 검출 · 커밋 신원 불일치 검출
  (체크섬은 2026-09 에 걷어냈다 — 게이트를 고치는 정상 작업을 CI 실패로 만들었고,
  CI 가 안내하는 복구가 그 수정을 지웠다. 실측은 아래 "체크섬을 걷어낸 근거")
- 린터 설정이 실 백엔드에서 14건, `govulncheck` 7건, `npm audit` 7건 검출
- 브랜치 보호 6개 required check 적용(private 레포에서도 가능함을 확인)
- **JVM·Python 어댑터** — Java+Gradle · Kotlin+Gradle+spotless · 2모듈 Gradle · Python
  각각을 만들어 통과와 실패를 양쪽 다 재현. spotless 위반이 `gradle check` 에서 잡히는
  것이 "품질 플러그인은 check 에 스스로 걸린다" 는 설계 근거의 증거다
- **`install.sh --update`** — baseline + 3-way 병합. 프로젝트 수정과 킷 변경이 겹치지
  않으면 둘 다 살아남고, 겹치면 충돌 마커를 남긴다. `--dry-run` 은 트리 해시 앞뒤 비교로
  무변경 확인. **2026-09 에 걷어냈다** — 병합이 풀려는 상황이 실제로는 안 일어났다(이슈 #38)
- **낡음 감지** — `SessionStart` 훅. 최신/낡음/모르는 rev/킷 없음 네 상태 실측
- **`statusLine.command` 의 `$CLAUDE_PROJECT_DIR` 전개** — 문서에 없어서 직접 재봤다
- **규칙 파일이 실제로 로드된다** — `/context` 의 Memory files 에
  `CLAUDE.md 76 tokens · AGENTS.md 2k tokens` 로 잡혔다(당시엔 두 파일이었다).
  킷의 "규칙 단일 출처" 주장이
  문서 인용이 아니라 증거를 갖게 됐다
- **검사별 실소요**(실 모노레포): eslint 6.5s · vitest 7.8s · tsc 2.5s · prettier 1.7s ·
  golangci-lint 0.9s · go test 0.3s(캐시 없으면 3.6s) · 전체 37~42s ·
  `--lint --staged` 로 커밋은 2.8s. 숫자는 `common/docs/verification-layers.md` 에 표로 있다
- `install-operator.sh` — 빈 홈 설치·재실행 멱등·기존 파일 보존(충돌은 `.ai-kit-new`)·
  소스 누락·복사 실패를 **격리된 `CLAUDE_HOME` 으로 확인**(실제 `~/.claude` 는 안 건드림)
- 훅이 실행권한 없이 커밋되면 강제가 꺼진다 — `core.fileMode=false` · 편집기 재생성
  두 경로로 재현하고, CI 의 `[ -x ]` 검사가 잡는 것까지 확인
