# ADR-0002: 킷 자신도 브랜치 → PR → 콜드 리뷰 → 머지로 간다

- **상태**: 채택
- **날짜**: 2026-08-23 (PR #1). 2026-09-12 에 `main` 룰셋으로 강제됐다 — 아래 「결과」

## 맥락

킷은 프로젝트에 「`main` 직접 커밋 금지 · 설정·CI·훅·게이트 스크립트는 글이 아니라
코드다 · 콜드 리뷰는 기본으로 돈다」를 적어 주면서, 자기 레포에서는 그 파일들만 골라
고치며 한 번도 안 돌렸다.

**리뷰 없이 8커밋을 밀었더니 기능이 죽어 있었다.** 2026-08-24 세션에서 킷 `main` 에
PR 없이 · 콜드 리뷰 없이 8커밋을 넣었고, 뒤늦게 콜드 리뷰를 돌리자 9건이 나왔다. 가장
나쁜 것은 `gate_go_tool` 함수가 통째로 사라진 것이었다 — 다른 함수를 슬라이스로
교체하면서 같은 구간의 무관한 함수를 같이 지웠고 호출부만 남았다. `GATE_STRICT` 기본값을
1 로 바꾼 직후라 **모든 Go 프로젝트가 커밋·푸시·CI 에서 실패**하는 상태로 올라가 있었고,
메시지는 이미 설치된 도구를 설치하라고 했다.

| | 찾은 것 |
| --- | --- |
| 작성자 자신(우연히 다시 보다) | 4건 — 전부 "덜 좋은 것" |
| 콜드 리뷰 | **9건** — 상당수가 "기능이 죽어 있음" |

같은 세션에서 커밋 린트가 엉뚱한 파일을 검사하고 있었던 것(범위가 `main...HEAD` 라
브랜치 두 번째 커밋부터 스테이지한 파일이 범위 밖), 충돌 마커 검사가 한글 파일명에서
조용히 통과하던 것(`core.quotePath` 기본값)도 콜드 리뷰가 잡았다.

**두 리뷰는 서로 다른 것을 잡는다.** 실 프로젝트의 PR 둘에서 잰 값이다(2026-08-21):

| | 1차 PR | 2차 PR |
| --- | --- | --- |
| 셀프(맥락 보유) | 3건 | 3건 |
| 콜드(맥락 없음) | **11건** | **7건** |

콜드가 크게 앞섰지만 **셀프만 잡은 것도 있다** — "PR 본문이 5개 커밋만큼 낡았다"는
맥락을 가진 쪽만 안다.

## 결정

킷 자신도 **브랜치 → PR → 콜드 리뷰 → 머지**로 간다. PR #1 부터다. 두 리뷰(셀프 ·
콜드)를 다 돌리고, 한 리뷰로 줄이지 않는다.

게이트 · 훅 · 권한 규칙을 킷 자신에게 거는 것은 이 결정과 별개로 두었다. 그것은 열린
결정으로 이슈 #4 에 있고, 이 레포에서는 킷의 스킬 · 훅 · `settings.json` 이 로드되지
않는다.

## 대안과 기각 사유

| 대안 | 기각 사유 |
| --- | --- |
| `main` 직접 커밋 + 작성자가 다시 본다 | 위 표. 작성자는 4건을 "덜 좋은 것"으로 봤고 콜드는 9건 중 "죽은 기능"을 봤다 |
| 리뷰 하나만 돌린다 | 콜드가 앞서지만 셀프만 잡은 것이 있다. 서로 다른 것을 잡는다 |
| 게이트 · 훅 · 권한 규칙까지 킷 자신에게 건다 | 이 레포에서는 그 계층들이 로드되지 않고, 걸려면 심링크 · 훅 경로 · `settings.json` 두 벌 문제를 각각 풀어야 한다(이슈 #4). PR 흐름과 분리해서 정한다 |

## 결과

킷 `CLAUDE.md` 하드룰의 첫 줄이 이것이다. 「누가 막나」는 처음에 `사람` 뿐이었다.

**2026-09-12 에 사람이 `main` 에 룰셋을 켰다.** enforcement 는 active, bypass 목록은
비어 있어 레포 주인에게도 적용된다, 대상은 기본 브랜치, 머지 방법은 스쿼시만, 승인 수는
0, required check 는 `tests` 하나, up to date 요구는 끔이다. 이 ADR 을 쓰며 다시 잰 값:

```
$ gh api repos/4estse4/ai-native-kit/rules/branches/main --jq '[.[].type]'
["deletion","non_fast_forward","pull_request","required_status_checks","required_linear_history"]

$ gh api repos/4estse4/ai-native-kit/rulesets --jq '.[] | {name, enforcement, target}'
{"enforcement":"active","name":"main","target":"branch"}
```

룰셋이 막는 것은 PR 없는 push · `tests` 가 빨간 채로 머지 · 스쿼시 아닌 머지 · `main`
삭제까지다. **콜드 리뷰를 돌렸는지는 룰셋이 안 본다.** 그것은 여전히 `사람` 이다.

룰셋 때문에 낡은 자리가 둘 있고, 그것은 이슈 #4 가 든다 — `.github/workflows/kit-tests.yml`
머리의 「이것은 required check 가 아니다」와, `merge-pr` 2절의 보호 확인이 클래식
엔드포인트만 봐서 룰셋을 「보호가 없다」로 보고하는 것. 룰셋의
`require_extra_approval_for_unattributed_changes` 가 `true` 라 머지가 막히면 그것부터 본다.

되돌리려면 룰셋과 `CLAUDE.md` 하드룰 첫 줄을 같이 건드려야 한다. 룰셋만 끄면 규칙은
남고 강제만 사라진다.
