# operator — 머신 단위 계층

킷은 세 계층이다. 이 디렉터리는 그중 **한 번 세팅하면 모든 프로젝트에 적용되는** 것들이다.

| 계층 | 범위 | 어디에 설치되나 |
|---|---|---|
| `core/` | 프로젝트 단위 | 대상 레포 (`.ai-kit/` · `docs/` · `.github/`) |
| `bindings/` | 도구 단위 | 대상 레포 (`.claude/` · `AGENTS.md`) |
| **`operator/`** | **머신·사람 단위** | **`~/.claude/`** |

프로젝트를 옮겨도 따라오는 것이라 프로젝트 킷과 섞으면 안 된다.
반대로 이 계층이 없으면, 새 머신에서 시작할 때마다 조용히 관측 능력이 빠진 채로 일하게 된다.

---

## statusline-command.sh

세션 상태를 한 줄로 띄운다. **기본값에서 벗어난 것만 보여준다** — 평상시엔 조용하고,
이상할 때만 눈에 띈다. (산출물 규칙 R1 과 같은 원리: 정상은 보고하지 않는다.)

띄우는 것 중 실전에서 값을 하는 것:

| 항목 | 왜 필요한가 |
|---|---|
| `5h:78% (2h12m)` · `7d:41%` | **타임드 과제에서 리밋에 걸리면 몇 시간이 날아간다.** 큰 작업 전에 보고 결정한다. |
| `ctx:62%` | 컨텍스트 압축이 임박했는지. 작업 분할 시점을 판단한다. |
| `effort:xhigh` · `fast` · `think:off` | 의도한 모드로 돌고 있는지. 무의식 중에 낮은 설정으로 오래 일하는 것을 막는다. |
| `agent:<name>` · worktree · PR 번호 | 지금 어느 맥락에서 말하고 있는지. 브랜치·에이전트를 오갈 때 오조작 방지. |

`~/.claude/settings.json` 의 `statusLine.command` 로 배선한다.

## CLAUDE.md (전역)

모든 프로젝트에 적용되는 작업 정책. 프로젝트별 규칙(`AGENTS.md`)과 섞지 않는다.

**규칙마다 왜 그렇게 정했는지 주석으로 남긴다.** 특히 도구의 기본 동작을 의도적으로
덮어쓸 때는 그 사실과 확인 방법을 적는다 — 나중에 동작이 이상할 때 여기부터 보게 된다.

## settings.json (전역)

모델·effort·statusline·플러그인 기본값. 프로젝트 `settings.json` 이 이것을 덮어쓴다.

## 설치

```bash
<kit>/operator/install-operator.sh
```

기존 파일은 덮어쓰지 않는다 — 다르면 `.ai-kit-new` 로 옆에 두고 알린다.
