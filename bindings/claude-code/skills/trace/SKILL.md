현재 검사 결과:
!`bash .ai-kit/gate/trace.sh 2>&1 || true`

SPEC:
!`cat docs/SPEC.md 2>/dev/null | head -200`

추적 매트릭스:
!`cat docs/traceability.md 2>/dev/null`

이 브랜치의 변경:
!`git diff main...HEAD --stat 2>/dev/null`

$ARGUMENTS

---

`docs/traceability.md` 를 실제 코드 상태에 맞게 갱신한다.

## 하는 일

1. **검사 결과의 불일치를 해소한다** — 추적표에 없는 요구를 행으로 추가하고,
   SPEC 에 없는 유령 행은 지우고, 없는 경로를 고친다.
2. **이번 변경이 도달시킨 요구의 상태를 올린다** — `미구현` → `부분` → `구현됨`.
   구현·테스트 칸에 **실재하는 경로**를 적는다.
3. **상태를 낮추는 것도 한다** — 코드를 지웠거나 요구를 다시 열었으면 낮춘다.

## 규칙

- **`미구현` 은 정상적인 상태다.** 시간이 없어서 못 한 것을 `구현됨` 으로 적지 마라 —
  추적표의 목적은 성적표가 아니라 **무엇이 빠졌는지 보이게 하는 것**이다.
- `구현됨` 으로 올리려면 **테스트 칸도 채워져야 한다.** 테스트 없이 구현만 있으면 `부분`.
- 코드를 확인하지 않고 상태를 올리지 마라. 해당 파일을 실제로 읽는다.
- 비고 칸에는 **왜** 미구현인지 한 줄. "시간 부족" 도 정직한 이유다.

## 끝

갱신 후 `bash .ai-kit/gate/trace.sh` 를 다시 돌려 통과를 확인하고,
상태가 바뀐 요구만 한 줄로 보고한다. **바뀐 것이 없으면 "변경 없음" 한 줄.**
