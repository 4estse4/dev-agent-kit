`docs/dev-log.md` 에 이번 작업 항목을 추가한다.

**위치는 기존 파일의 순서를 따른다** — 위 "기존 dev-log 항목 순서" 출력에서
날짜가 오름차순이면 파일 끝에, 내림차순이면 맨 위 항목 다음에 넣는다.
순서를 임의로 정하지 마라. 파일이 비어 있으면 오름차순(최신이 아래)으로 시작한다.

**이 PR 이 닫는 이슈가 `docs/plan/` 의 지금 단계 문서 「작업 목록」에 있으면 그 항목을
지우고(항목이 헤딩이면 그 블록째다), 지운 것을 이 dev-log 항목의 「작업」 줄 끝에 「계획에서 지움:
이슈 #N」으로 적는다.** 닫는 이슈는 위 PR 본문의 `Closes #N` 과, 연 뒤 라운드에서 사람이 이 PR 로
끝내기로 정한 이슈(`merge-pr` 3절이 머지 뒤에 닫거나, 봇 설정이 있으면 스쿼시 커밋 메시지의 `Closes` 로
머지가 닫는다)다. 뒤의 것은 본문에 없으므로 사람 계정 코멘트(`open-pr` 3.5)에서 사람이 정한 것을
보고 안다. 이 스킬은 `merge-pr` 보다 먼저 실행되므로 결정 코멘트에서는
알 수 없다. 다른 절(위험 표 등)에 있는 같은 번호와, 「작업 목록」 안에서 다른 항목의 이유에 든 같은
번호는 그대로 둔다. 항목 모양은 문서마다 다르다 — `docs/plan/0000-template.md` 의 항목은 `### T1` 헤딩과 불릿 둘이고, 번호 한 줄로
쓴 문서도 있다. 항목에 이슈 번호가 없으면 지울 것이 없다. 그때는 건너뛴다.
**지금 단계 문서는 `docs/plan/README.md` 가 가리키는 파일이다.** README 가 없거나 단계를
가리키지 않으면 이 단락을 건너뛴다.

    ls docs/plan/README.md 2>/dev/null || echo "(README 없음 — 건너뛴다)"
    grep -nE '#<N>([^0-9]|$)' docs/plan/<README 가 가리키는 파일>   # 그 번호가 항목인 것 하나만 지운다(헤딩이면 블록째). 다른 항목의 이유에 든 같은 번호는 둔다. 이 출력은 증거로 붙이지 않는다

## 형식

```
## YYYY-MM-DD — <주제> (PR #N)

- **작업**: <무엇을 만들었나. 한두 줄.>
- **채택**: `[AI]` <제안> → <누가 정했나>. <이유>
- **폐기**: `[AI]` <제안> → 폐기. <누가 무엇을 짚었나>
- **게이트가 찾아낸 것**: <린터·테스트·CI 가 찾아낸 것>
- **사람이 찾아낸 것**: <게이트가 찾아내지 못해 사람이 발견한 것 + 무엇을 하다가 발견했나 + 그래서 바뀐 것>
- **이관**: <안 하기로 한 것 + 어디에 기록했나>
```

## 규칙

- **화자를 반드시 표시한다** (`[AI]` `[사람]`). 둘이 함께 정한 것은 제안한 쪽과 승인한 쪽을 각각
  적는다(「`[AI]` 제안 → 사람이 승인」). 나중에 이 로그만 읽고
  누가 제안하고 누가 정했는지를 알 수 있어야 한다 — 결론만 있으면 못 한다.
- **사람이 정한 것을 인용할 때 질문 창 보기에 세션이 붙인 추천 표시(「(추천)」 · `(Recommended)` 같은 것)는
  따옴표에 넣지 않는다.** 사람이 한 말이 아니다. PR 이 열리기 전에 정한 것은 사람 계정 코멘트(`open-pr`
  3.5)에 없어 이 항목에만 인용되므로, 여기서 떼지 않으면 표시가 기록에 남는다.
- **"게이트가 찾아낸 것" 과 "사람이 찾아낸 것" 을 나눈다.** 이게 쌓여야 검증 체계를
  데이터로 말할 수 있다. 해당 없으면 그 줄을 지운다(빈 줄로 두지 않는다).
- **「채택」 · 「폐기」 · 「사람이 찾아낸 것」에는 질문 창을 어떻게 다뤘는지(창을 닫았다 · 다시 물었다 · 고친 판과 처음
  판 중 어느 쪽을 골랐다)를 적지 않는다.** 「채택」에는 사람이 무엇을 정했는지를, 「사람이 찾아낸 것」에는 사람이 무엇을
  짚었고 그래서 무엇이 바뀌었는지를 적는다. 창을 다룬 경위는 무엇이 바뀌었는지를 말하지 않고, 적으면 읽는 쪽이 창을 다룬
  말 사이에서 바뀐 것을 가려 읽어야 한다. 「무엇을 하다가 발견했나」는 발견에 이른 길이다 — 계획이나 PR 본문 초안을 읽다가 ·
  diff 를 읽다가 · 직접 실행해 보고 · 두 리뷰의 코멘트를 대조하다가.
- 해당 없는 항목은 **줄째로 지운다.** "없음" 을 채워 넣지 않는다.
- 리뷰에서 **보류·기각한 것도 짧게 남긴다.** 채택만 남기면 판단 과정이 사라진다.
- 항목 하나가 15줄을 넘으면 대개 과하다.
