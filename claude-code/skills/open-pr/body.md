## 2. PR 을 연다

여는 것은 제목과 본문 전문을 승인받은 뒤다(`SKILL.md` 의 「꼭 지킬 것」). PR 을 연 뒤에는 본문을 고치지
않으므로 틀린 채로 열면 고칠 자리가 없다. 승인받으면 `gh pr create` 로 열고,
**1라운드(3절)는 그 뒤 곧바로 진행한다.** 여는 것과 1라운드 사이에 다시 묻지 않는다 — 열었는데
리뷰가 진행되지 않는 상태는 쓸모가 없다. 어떤 행동에 사람의 승인이 필요한지와 그 기준은
`docs/process/verification-stages.md` 6.3 에 있다.

**권한 프롬프트는 이 승인을 대신하지 못한다.** `gh pr create` 는 `settings.json` 의 `ask` 에
있어 프롬프트가 표시되지만, 본문은 파일로 전달하므로(아래) 프롬프트에 보이는 것은 **파일 경로뿐이다.**

제목은 브랜치 전체의 목적을 Conventional Commits 스타일로 쓴다.
**제목에 이슈 번호를 쓰지 않는다.** 스쿼시 제목 끝에 `merge-pr` 이 PR 번호를 `(#N)` 으로 붙이므로,
이슈 번호까지 있으면 같은 표기 둘이 구분되지 않는다. 이슈 번호는 본문의 `Closes #N` · `Refs #N` 과 결정
코멘트에 적는다.

본문은 **아래 일곱 절만** 쓴다. 브랜치 전체를 요약하되, 절마다 아래 꺾쇠(`< >`) 안의 설명대로 쓴다. 절 이름은
짧은 명사이고 질문으로 쓰지 않는다.

```markdown
## 문제
<무엇이 틀렸거나 필요한가. 목록 항목 1~3개. 끝내는 이슈는 `Closes #N`, 일부만 하는 이슈는 `Refs #N`>

## 해결
<무엇을 어떻게 바꿨나. 목록 항목 1~3개>

## 결정
| 쟁점 | 선택 | 대안 | 이유 |
| --- | --- | --- | --- |
| <정한 것> | <고른 것> | <고르지 않은 것> | <한 구절> |

## 리뷰 포인트
| 영역 | 위험 | 이유 |
| --- | --- | --- |
| <리뷰가 먼저 볼 자리> | <높음 · 중간 · 낮음> | <한 구절> |

## 영향
<바뀌는 동작 · 배포하는 파일의 이름을 바꿨으면 무엇이 남는지. 목록 항목. 없으면 "없음">

## 한계
<안 한 것 · 확인 못 한 것 · 다른 PR 과의 순서. 목록 항목. 없으면 "없음">

## 검증
<명령마다 `evidence.sh --fold` 가 덧붙인 접힌 블록. 결과 한 줄만 보인다>

- 새 테스트: <`SKILL.md` 에 주입된 새 테스트 목록에서 추린 이름들. 없으면 "없음">
```

| 절 | 담는 것 |
| --- | --- |
| 결정 | 산문에 흩어지던 판단. PR 을 열기 전에 사람이 정한 것과 안 하기로 정한 것도 여기 적는다. 없으면 표 대신 「없음」 |
| 리뷰 포인트 | 바뀐 파일을 하는 일끼리 묶은 영역. `SKILL.md` 에 주입된 --stat 을 참고하되 파일 목록은 옮기지 않는다(Files 탭에 있다) |
| 한계 | 자동 검증이 확인하지 않은 것도 여기다. 직접 확인한 것은 「검증」에 접어 붙인다 |

### 본문은 파일로 만들고 출력은 명령이 덧붙인다

**손으로 옮긴 출력이 잘렸다.** 한 PR 본문에서 18줄 출력의 앞 네 줄이 세 번 빠졌다. 「그대로
붙인다」는 규칙이 이미 있었는데도 빠졌다. 주입으로 온 게이트 출력은 정확했고 잘린 것은 전부
손으로 옮긴 쪽이었다. 그래서 옮기는 단계를 없앤다.

1. 조각을 둘 새 디렉터리를 만든다. 레포의 git 디렉터리 안이라 커밋되지 않고 `git status` 에도
   나오지 않는다. 그 대신 보호 경로다. 조각을 쓰고 고칠 때마다 `default` · `acceptEdits` 모드에서는
   권한 프롬프트가 표시되고, `auto` 에서는 분류기가 정하고, `dontAsk` 에서는 거부돼 본문을 못
   만든다. `allow` 로 미리 풀 수 없다(공식 문서의 protected paths). 셸 변수에
   담지 말고, 출력된 경로를 이후 명령에 그대로 넣는다(3.1 과 같은 이유다):

       mktemp -d "$(git rev-parse --absolute-git-dir)/pr-body.XXXXXX"

2. 글은 `Write` 로 조각 파일에 쓴다. 출력은 `evidence.sh` 가 그다음 조각에 덧붙인다. 조각
   파일 이름은 이을 순서대로 짓는다(`10-head.part` · `20-gate.part` · `30-rest.part` …). 명령은 따옴표 heredoc
   으로 **한 번만** 전달한다. 보이는 명령과 실행되는 명령이 같다. `$ 명령` · 출력 · `rc=N` 이 코드
   블록째 들어간다. `--fold` 는 그 블록을 접고 결과 한 줄을 `<summary>` 에 두며, 스크립트가 그 끝에 `(rc=N)` 을
   붙인다. `<스킬 디렉터리>` 자리에는 이 파일을 읽어 온 디렉터리의 경로를 넣는다(`SKILL.md` 의 「꼭 지킬 것」):

       bash <스킬 디렉터리>/evidence.sh --fold "<결과 한 줄>" <디렉터리>/20-gate.part <<'CMD'
       bash .kit/gate/gate.sh
       CMD

   「검증」의 명령은 하나마다 `--fold` 로 따로 부른다. 결과 한 줄에는 출력에서 읽은 것(통과 · 실패한 수 · 찾은 것)만
   쓴다. 접힌 블록은 그 한 줄만 보이고, 펼치면 명령과 출력이 있다. 실패하는 명령은 `rc` 가 본문에
   남고 스크립트도 그 코드로 끝난다.

   **`evidence.sh` 를 `allow` 에 넣지 마라.** 받은 글을 `bash -c` 로 실행하므로 권한 규칙이 그
   안을 못 본다. 허용해 두면 그 안의 `gh pr merge` · `git push --force` 가 프롬프트 없이 실행된다.
   그래서 스크립트가 레포 · 사람 · 관리 settings 파일의 `ask` · `deny` 규칙 글자가 보이는 명령을
   거부한다. 서버 관리 settings · macOS 구성 프로필 · 실행할 때 준 `--settings` · `--disallowedTools` 의 규칙은
   이 스크립트가 대조하지 않으므로, `evidence.sh` 를 allow 에 넣으면 그 규칙이 지켜지지 않는다. 증거는 읽기만
   하는 명령이다. 부를 때마다 권한 프롬프트가 표시될 수 있다. **거부된 명령의 출력은 증거로
   싣지 말고 무엇을 확인했는지 글로 적는다.** 직접 실행해 출력을 손으로 옮기면 이 절이 없앤 일이 다시 생긴다.
3. 조각을 이름 순서로 잇는다: `awk 1 <디렉터리>/*.part > <디렉터리>/body.md`
   `cat` 이 아니라 `awk 1` 인 이유: `Write` 로 쓴 조각이 줄바꿈 없이 끝나면 `cat` 은 다음 조각의
   여는 펜스(```)를 그 줄에 붙여 코드 블록이 열리지 않는다. `awk 1` 은 조각 끝에 줄바꿈을 채운다.
4. 사람에게 보이는 것은 이 `body.md` 전문이다. 고칠 곳이 나오면 그 조각을 고치고 3을 다시
   실행한다. 승인받으면 연다:

       gh pr create --title "<제목>" --body-file <디렉터리>/body.md

### 본문 작성 규칙

- **검증 절은 증거다.** "테스트 통과함" 같은 주장을 쓰지 말고 게이트를 `evidence.sh --fold` 로 실행해
  그 출력을 덧붙인다. 게이트가 실패한 채로 PR 을 열지 않는다.
- **「한계」를 비워 두지 마라.** 시각·레이아웃·여러 화면을 오가는 흐름은
  대개 자동 검증 밖이다. 직접 확인했으면 「검증」에 그 명령을 접어 붙이고,
  확인 못 했으면 「한계」에 못 했다고 쓴다. 적지 않으면 확인하지 않은 것이 있다는 사실이 사라진다.
- **접히지 않은 부분은 개조식으로 쓴다.** 목록 항목 하나 · 표 칸 하나에 한 가지를 한 줄로 쓰고, 산문 문단을 두지
  않는다. 접힌 블록(리뷰 전문 · 「승인한 표」 · 명령 출력) 안은 예외다. 길이는 길이 훅(`post_length.sh`)이 GitHub 이
  그린 글자로 세어, 접히지 않은 부분의 총량이나 한 줄이 상한을 넘으면 `gh pr create` 를 막는다. 접힌 블록은
  `<summary>` 만 센다. 상한은 그 훅이 쓰는 `.claude/hooks/kit/post_length.py` 머리에 있다.
- **이 PR 이 끝내는 이슈가 있으면 「문제」에 `Closes #N` 을 쓴다.** 머지가 그 이슈를
  닫는다. 이슈의 일부만 하는 PR 에는 `Closes #N` 대신 `Refs #N` 을 쓴다 — 그 PR 이 열려 있는 동안 다른 세션의
  「다음 일」 목록이 이 번호로 그 이슈를 맡은 일로 알고 후보에서 뺀다. 연 뒤 라운드에서 끝내게 된 이슈는 본문을 고치지
  않고, 그 결정을 창(머리말 「끝낼 이슈」)으로 받아 사람 계정 코멘트로 올린다(3.5). 마지막 라운드 뒤에
  정했으면 그때 올린다. `dev-log` 는 사람 계정 코멘트에서 그 이슈를 골라 계획에서 지우고, `merge-pr` 은 그
  이슈를 스쿼시 커밋 메시지의 `Closes` 로 넣어 머지가 닫게 한다.
- **이 본문은 다음 단계에서 diff 와 대조된다.** 지키지 못할 주장을 쓰지 마라.
- **PR 을 연 뒤에는 본문을 고치지 않으므로(`SKILL.md` 의 「꼭 지킬 것」) 라운드가 바꿀 값을 본문에 적지 마라** —
  설정 파일의 내용을 복사해 붙이는 것 같은 파생 출력이 그것이다. 그 값이 바뀌어도 본문은 그대로라, `$` 가 붙어
  실행 결과처럼 보이는 거짓이 남는다. 붙일 것은 **이 시점에
  실행한 게이트 출력**이고, 그건 낡는 것이 아니라 그때의 기록이다.
  이유는 `docs/process/verification-stages.md` 4.
