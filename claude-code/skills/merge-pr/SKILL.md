## 꼭 지킬 것

**단계를 시작하기 전에 아래 「차례」에서 그 단계의 파일을 읽는다.** 이 파일에는 꼭 지킬 것 · 차례 · 주입 · 1. PR 번호
확정만 있고, 그 밖의 단계마다 할 일과 그 까닭은 그 단계의 파일에 있다.

**「차례」의 보조 파일은 `${CLAUDE_SKILL_DIR}` 에서 읽는다.** 앞 문장에 경로 대신 변수 이름이 그대로 보이면 이
`SKILL.md` 가 든 디렉터리에서 보조 파일을 읽는다. `Read` 로 연 파일에서는 변수가 치환되지 않으므로, 보조 파일에 나오는
`<스킬 디렉터리>` 자리에는 보조 파일을 읽어 온 디렉터리의 경로를 넣는다. 증거를 덧붙이는 `evidence.sh` 와 조각을 둘
디렉터리를 만드는 `drafts.sh` 는 `open-pr` 의 것이라 그 옆 디렉터리(`${CLAUDE_SKILL_DIR}/../open-pr`)에 있다.

**컴팩션 뒤에는 하던 단계를 이어 가기 전에, 「차례」에서 그 단계의 파일을 `Read` 로 다시 읽고, 그 파일이 절 번호나
파일 이름으로 가리키는 「차례」의 파일도 다시 읽는다.** 컴팩션 뒤 컨텍스트에는 이 `SKILL.md` 가 앞부분만 다시
들어오거나 아예 들어오지 않고, 읽어 둔 보조 파일의 내용은 요약되어 절차가 빠질 수 있다.

**지시가 있어야 이 스킬을 실행한다.** 두 리뷰가 `Approve` 를 냈다는 것은 그 리뷰들의
의견이지 허락이 아니고, CI 의 검사가 모두 통과한 것도 허락이 아니다. 허락은 사람이 한다.

지시 없이 이 스킬을 실행했으면 머지하지 말고 **`open-pr` 3.5 대로 사람에게 보고하고 멈춘다.** 예외는 하나다 —
다음 작업을 시작할 때 머지된 PR 을 정리하려고 부르는 것(3절 「다음 작업을 시작할 때 auto-merge 가 켜진 열린 PR 과
머지된 PR 을 본다」)은 지시 없이 부른다. 그때 2절은 `MERGED` 를 보고 4절과 5절만 한다.

레포에 봇 설정(`.claude/bot.json`)이 있으면 머지 승인은 사람 계정의 Approve 다. 세션은 결정 코멘트를 올리고
GitHub auto-merge 를 켠 뒤 Approve 를 요청하고, Approve 가 달리면 GitHub 이 머지한다(3절 「봇 설정이 있을
때」). 사람의 지시는 그 절차를 시작하라는 것이고, 머지를 허락하는 것은 Approve 다.
