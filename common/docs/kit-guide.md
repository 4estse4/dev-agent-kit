# 이 킷이 무엇을 하고, 무엇을 안 하나

설치 직후 한 번 읽는 문서다. **킷이 자동으로 해주는 것 · 프로젝트가 채워야 하는 것 ·
킷이 아직 못 하는 것**을 구분한다. 구분이 없으면 안 되는 것을 된다고 믿게 된다.

## 1. 자동으로 실행되는 것 — 손댈 것 없음

| 시점 | 무엇 | 막나 |
|---|---|---|
| 파일 편집 직후 | 포맷(gofmt·prettier·ruff·ktlint) | **못 막는다** — 편집이 끝난 뒤에 실행되기 때문이다. 포매터가 없으면 알린다 |
| `git commit` | 보호 브랜치 · 커밋 신원 · 충돌 마커 · 시크릿 · **린트** | 막는다 — git 훅을 켠 clone 에서(3절) |
| `git push` | 위 + 타입 · 테스트 · 빌드 | 막는다 — git 훅을 켠 clone 에서(3절) |
| 세션 시작 · 세션의 `git commit` · `git push` | git 훅이 꺼진 레포인지(`core.hooksPath` 가 `.kit/git-hooks` 가 아님) | 세션 시작 때 알리고, 켤 때까지 세션의 커밋 · 푸시를 막는다 |
| CI | 같은 게이트 + 요구 추적 | 우회할 수 없다. 다만 머지 자체는 브랜치 보호를 켜야 막힌다 |

**도구가 없으면 검사는 실패한다.** 도구 부재는 통과가 아니라 "검사되지 않았다" 이다.
로컬만 도구 없이 통과시키면 로컬에서 통과한 커밋이 CI 에서 실패하고, 고쳐서 다시 푸시하는
데 CI 와 사람의 시간이 든다.

```bash
bash .kit/gate/install-tools.sh              # 이 레포에 필요한 것만 설치
bash .kit/gate/gate.sh --lint                # 린트만 (커밋 훅이 부르는 것)
bash .kit/gate/gate.sh --all                 # 전부 (CI 가 부르는 것)
```

불가피할 때만 `KIT_ALLOW_MISSING_TOOLS=1` 로 도구가 없는 검사를 건너뛰게 한다. **무엇이 검사되지 않는지 출력된다.**
Claude Code 세션 안에서는 이 변수를 받지 않는다 — 도구를 설치하거나, 사람이 세션 밖 터미널에서 실행한다
(`verification-stages.md` 6.4).

## 2. 프로젝트가 채워야 하는 것

| 파일 | 무엇을 | 안 채우면 |
|---|---|---|
| `CLAUDE.md` 의 `<프로젝트명>` | 이름 | 표시만 어색 |
| `CLAUDE.md` 의 **하드룰 표** | 이 프로젝트에서 절대 하면 안 되는 것 + **누가 막나** | 규칙이 없는 것과 같다 |
| `CLAUDE.md` 의 스택·명령 | 실행·테스트 명령 | 에이전트가 매번 물어본다 |
| `docs/SPEC.md` | 요구 ID(`R-<영역>-<번호>`) | 추적표가 빈 채로 통과한다 |
| `docs/traceability.md` | SPEC 의 모든 요구에 한 행 | CI 의 `trace` 잡이 실패한다 |
| `.claude/bot.json` | 봇 계정으로 쓸 GitHub App 의 ID 와 이름(6절). 쓰지 않으면 만들지 않는다 | 세션과 사람이 한 계정을 써서 GitHub 에서 세션의 글과 사람의 결정이 구분되지 않는다 |
| `.kit/gate.conf` | 게이트 설정 — `go test` · `pytest` 에 더할 플래그, `check` 대신 실행할 gradle 태스크, 모듈을 찾을 때 건너뛸 디렉터리 이름 목록(어느 깊이에서든 그 이름의 디렉터리를 모두 건너뛴다. 기본 목록을 통째로 바꾼다). 형식은 `.kit/README.md`. 필요 없으면 만들지 않는다 | 기본값으로 검사한다 |

> **하드룰마다 누가 막나를 반드시 적는다.**
> **`리뷰`·`막는 것 없음` 만 적힌 규칙은 안 지켜진다고 가정하고 계획을 정하라.** 불편하면 기계가 막게 바꾼다.
> 어휘와 각각의 우회는 `verification-stages.md` 3.3 에 있다.

`docs/process/` 의 두 문서가 그 이유를 설명한다 — `artifact-rules.md`(R1~R7)와
`verification-stages.md`(어느 검사를 어디에 둘지, 측정한 시간 포함).

## 3. 사람이 직접 할 일

킷이 대신하지 못하는 일이다. 첫 표는 모든 레포에서 하고, 둘째 표는 봇 계정을 쓰는 레포에서 사람이 하는 일이다(6절).

| 언제 | 어디서 | 무엇을 | 안 하면 |
|---|---|---|---|
| 설치 전 | 터미널 | `git config user.email` 이 이 레포에서 쓸 이메일인지 본다(아래 「커밋 신원」) | 훅이 틀린 이메일을 정답으로 지킨다 |
| 설치 전 | 로컬 · 레포 루트 | Go 를 쓰면 `go_min` 이상의 Go 를 설치하고, Node · Python 을 쓰면 루트에 `.nvmrc` · `.python-version` 을 둔다(아래) | CI 의 그 언어 잡이 이유를 말하며 멈추고, 낮은 Go 로 빌드한 로컬 도구가 멈춘다 |
| 설치 때 | 터미널 | `install.sh <경로> --protect` 로 브랜치 보호를 설정한다 | 로컬 훅은 `--no-verify` 로 우회되고, CI 의 검사가 실패해도 머지된다 |
| clone 한 뒤 | 터미널 · 레포 루트 | `git config core.hooksPath .kit/git-hooks` 로 git 훅을 켠다. 그 설정은 clone 에 따라오지 않는다. 세션은 시작할 때 알리고 켤지 묻는다 | 커밋 · 푸시 전 검사가 실행되지 않고, 세션의 `git commit` · `git push` 는 켤 때까지 막힌다 |

> **주의 — 킷은 봇과 함께 쓴다.** 아래 표는 봇 설정(`.claude/bot.json`)을 둔 레포의 일이다. 봇 설정이 없으면
> 세션과 사람이 한 계정이라 사람의 결정이 사람 계정 코멘트로 남지 않고, 라운드 코멘트의 `(사람)` 인용이
> 막히고, 리뷰 라운드와 머지가 끝까지 가지 못한다(6절 머리).

| 언제 | 어디서 | 무엇을 | 안 하면 |
|---|---|---|---|
| 처음 한 번 | GitHub 의 App 설정 | GitHub App 을 만들고 권한을 정한다(6절 「켜는 법」 1) | 세션이 봇 계정에 연결되지 않아 gh 로 쓰거나 푸시하지 못한다 |
| 머신마다 | `~/.config/<App 이름>/key.pem` | App 의 개인키를 둔다(6절 2) | 그 머신의 세션이 연결되지 않는다 |
| 레포마다 | GitHub 의 App 설치 설정 | 저장소 목록에 레포를 더한다(6절 3) | 세션 시작 때 「App 설치에 이 레포가 없다」가 나온다 |
| 레포마다 | 레포 | `.claude/bot.json` 을 커밋하고 세션을 다시 시작한다(6절 4 · 5) | 세션과 사람이 한 계정을 쓴다 |
| 봇 설정을 커밋한 뒤 레포마다 | 터미널 | `install.sh <경로> --protect` 를 다시 실행해 사람의 Approve 를 요구하게 하고, 레포 설정 「Allow auto-merge」 · 「Automatically delete head branches」를 켠다(6절 6). 리뷰하는 사람이 여럿이면 필요 승인 수를 GitHub 의 브랜치 보호 설정에서 올린다 | GitHub 이 사람의 Approve 없이 머지를 받는다. 세션이 auto-merge 를 켜지 못해, 사람이 Approve 한 뒤 세션의 창에서 「Approve 했다」를 골라야 머지된다 |
| App 권한을 바꿨을 때 | GitHub 의 App 설치 설정 | 새 권한을 승인한다(6절) | 설치 토큰이 옛 권한이다 |
| 사람의 git 설정이 github.com 의 https 를 SSH 로 바꿀 때 | 레포 | 더 긴 규칙으로 이 레포에서만 끈다(6절 「세션의 git 이 닿는 곳」) | 세션의 푸시가 막힌다 |
| 리뷰 라운드마다 | 세션 · PR 웹 | 세션이 띄운 「N라운드 코멘트」 창에서 다음 할 일을 고른다. 고른 보기가 그대로 사람 계정 코멘트로 올라간다. PR 웹에 쓰려면 그 창에서 「PR 웹에 쓴다」를 고르고, 쓴 뒤 「PR 웹 코멘트」 창에서 「PR 웹에 썼다」를 고른다(6절) | 세션이 다음 단계를 시작하지 않는다 |
| 머지 전 | PR 웹 · 터미널 · 세션 | 세션이 요청한 head 를 Approve 하고, 세션의 「PR #N 최종 검토」 창에서 「Approve 했다」를 고른다. 세션이 auto-merge 를 켰으면 Approve 하는 순간 GitHub 이 머지하고, 켜지 못했으면 창에서 고른 뒤 세션이 Approve 를 확인해 머지한다(세션의 요청 블록이 어느 쪽인지 적는다). 머지됐으면 세션이 로컬 브랜치를 정리하고 「다음 일」 창으로 묻는다. Approve 뒤에도 브랜치가 뒤처지거나 충돌해 머지되지 못하면 사람이 창에서 고른 뒤 세션이 그 까닭을 알린다. PR 브랜치에 직접 푸시하려면 먼저 세션에 알려 auto-merge 를 끄게 하고, 푸시했으면 세션이 다시 푸시한 뒤에 Approve 한다(6절 6). PR 웹의 「Update branch」 · 「Resolve conflicts」도 PR 브랜치로 가는 사람의 푸시다 | 머지되지 않는다. auto-merge 를 켠 채 사람이 푸시하면 다른 리뷰어의 Approve 로 옛 결정 코멘트대로 머지된다 |

**커밋 신원.** `install.sh` 는 설치 시점의 `git config user.email` 을 `.kit/identity` 에
기록하고, 이후 훅이 그 값을 정답으로 검증한다. **틀린 값이 기록되면 훅이 틀린 값을 지켜준다.**

```bash
git config user.email      # 이 레포에서 쓸 이메일이 맞는지 먼저 본다
```

다르면 `git config user.email '<쓸 이메일>'` 로 고치고 `.kit/identity` 를 지운 뒤
`install.sh` 를 다시 실행한다.

**Go 버전.** 킷은 `.kit/gate/tool-versions` 의 `go_min` 보다 낮은 Go 를 지원하지 않는다. 그보다
낮은 go 로는 킷이 핀한 Go 도구가 설치되지 않거나, golangci-lint 의 gofumpt 가 기준으로 삼는 Go 의
gofmt 와 포맷이 어긋나 게이트를 통과하지 못하는 코드가 생긴다. `go.mod` 는 레포 어디에 있어도 되고
여럿이어도 된다. CI 는 설치할 Go(`toolchain` 줄이 있으면 그 버전, 없으면 `go` 줄)가 가장 높은 것으로
Go 를 설치하고, 그 버전이 `go_min` 보다 낮으면 Go 를 설치하는 잡마다 그 이유를 말하며 멈춘다. `go`
줄이 `1.27` 처럼 패치가 없으면 setup-go 가 그 계열의 패치 하나를 설치하므로 `go_min` 과 계열끼리 견준다.

로컬에 설치한 Go 도 `go_min` 이상이어야 한다. 그보다 낮은 Go 에서 `install-tools.sh` 를 실행하면
Go 도구가 그 Go 로 빌드되고, 그 golangci-lint 는 go 줄이 `go_min` 인 모듈에서 「the Go language
version … used to build golangci-lint is lower than the targeted Go version」으로 멈춘다. 레포 안에서
`go version` 은 go.mod 를 따라 전환된 Go 를 보여 주므로 설치한 Go 가 낮은 것이 잘 드러나지 않는다.
`install-tools.sh` 는 이미 있는 도구를 다시 설치하지 않으므로, Go 를 올린 뒤에는 그 Go 로 빌드한
도구(`goimports` · `golangci-lint` · `govulncheck`)를 지우고 다시 실행한다.

**Node · Python 버전.** CI 는 잡마다 런타임을 하나만 설치하고, 그 버전을 레포 루트의 `.nvmrc` ·
`.python-version` 에서 읽는다. `package.json` · `pyproject.toml` 이 하위 디렉터리에 있어도 이 두 파일은
루트에 둔다. 없으면 그 언어의 런타임을 설치하는 잡이 이유를 말하며 멈춘다.

## 4. 킷이 안 하는 것 — 기대하지 마라

- **Java** — `ktlint` 는 `.kt` 만 본다. Java 소스는 컴파일·테스트만 되고 **린트 검사를 받지 않는다.**
- **런타임 설치** — Go·JDK·Node·Python 은 프로젝트가 요구하는 버전이 있다. 킷은 설치하지 않는다.
- **`pytest`·`mypy`** — 프로젝트 의존성이다. `uv.lock`·`poetry.lock`·`[dependency-groups]`·
  `[project.optional-dependencies]`·`requirements-dev.txt` 중 하나로 선언해야 CI 가 설치한다.
- **빌드 래퍼** — Gradle 은 `./gradlew` 를 **커밋해야** 한다. 없으면 CI 가 막는다
  (`./gradlew` 가 없으면 러너 이미지에 든 Gradle 을 쓰게 되어 버전이 고정되지 않기 때문).
- **docker/compose** — 서비스 구성은 프로젝트마다 달라 템플릿을 주지 않는다.
- **e2e** — 무엇을 e2e 로 볼지는 프로젝트가 정한다.
- **낡음 감지는 로컬 전용** — 설치에 쓴 로컬 킷 클론에 설치 뒤 새 커밋이 생겼는지는 세션 시작 시 한 줄로
  알린다. 그 클론을 갱신하지 않으면 알리지 않고, CI 는 모른다.
- **macOS Finder 로 만든 한글 이름의 모듈 폴더** — 디스크에는 자모(NFD)로, git 에는 음절(NFC)로
  남을 수 있다. 그러면 로컬에서 실행되는 게이트(pre-commit · pre-push, `open-pr` 이 PR 본문에 붙이는
  출력)가 그 폴더의 변경을 못 알아보고 그 모듈을 건너뛸 수 있다. CI 는 전체를 검사하므로
  거기서 본다.

## 5. 킷이 바뀌면

```bash
<kit>/install.sh <이 레포 경로> --dry-run   # 무엇이 달라질지만
<kit>/install.sh <이 레포 경로>             # 다시 설치
```

`--dry-run` 은 아무것도 바꾸지 않고, 킷이 놓을 파일을 임시 트리에 만들어 이 레포와
대조한다 — **설치·교체·보존·동일·삭제** 다섯 칸으로 세고 diff 를 붙인다. 실제 실행도
같은 낱말을 쓰므로 두 출력을 그대로 견줄 수 있다.
그 트리는 남으므로 **거기서 직접 병합하면 된다.**

`.kit/**` 와 킷이 `.claude/` 에 놓는 파일(`settings.json` 은 빼고), `docs/process/**` 는 킷 소유라
**재설치가 덮어쓴다** — 여기 손댄 것은 다음 설치에서 사라진다. `.kit/` 아래에서 `identity` 와 `gate.conf` 는
프로젝트 소유라 재설치가 남긴다. 고칠 것이 있으면 킷 레포에
이슈나 PR 로 올려라. `CLAUDE.md`·`.claude/settings.json`·CI·린터 설정과 템플릿으로 놓는 `docs/` 문서 · PR
템플릿은 **프로젝트 소유**라 건드리지 않는다 — 킷의 것과 다르면 킷의 것을 `<파일>.kit-new` 로 옆에 두고,
가져올지는 사람이 정한다. **자동 병합은 하지 않는다.**

**킷 파일로 덮어쓰지 마라**: 그 파일들엔 프로젝트 고유 설정이 들어 있다.

## 6. 봇 계정과 사람의 승인

레포에 봇 설정(`.claude/bot.json`)이 있으면 세션이 GitHub 에 쓰는 글은 봇 계정(GitHub App)으로
올라가고, 사람의 결정은 사람 계정으로 남는다 — 리뷰 라운드 뒤의 결정은 사람 계정 코멘트로, 머지 승인은
PR 의 Approve 로. 그래서 GitHub 이 기록한 글쓴이로 세션의 글과 사람의 결정이 구분된다.

> **주의 — 킷은 봇과 함께 쓴다.** 봇 설정이 없으면 세션과 사람이 한 계정을 쓰고, 이 절의 것은 하나도 동작하지
> 않는다. 사람의 결정이 사람 계정 코멘트로 남지 않고, `(사람)` 인용을 확인하는 훅이 그 인용이 든 라운드 코멘트를 막는다 —
> 글쓴이로 사람의 글을 가려낼 수 없어 대조할 원본이 없다. 콜드 리뷰 보고도 기록되지 않아, 콜드 전문을 대조하는 훅이
> 라운드 코멘트를 모두 막는다. PR 작성자가 사람 자신이라 Approve 로 머지를 승인할
> 수도 없다(「Pull request authors cannot approve their own pull requests.」). 그래서 리뷰 라운드와 머지가 끝까지
> 가지 못한다 — `open-pr` 3.6 의 5 가 사람 계정 코멘트를 세지 못해 푸시하지 않고, `merge-pr` 2절은 Approve 를
> 판정하지 못해 멈춘다.

**사람의 결정을 남기는 두 길.** 리뷰 라운드가 끝나면 세션이 보고하고 사람이 다음 할 일을 정한다(`open-pr`
3.5). 어느 길로 남겨도 세션은 그 코멘트를 읽고 한 라운드 더 진행하거나 머지 단계를 시작한다.

1. 세션의 질문 창에서 고른다. 질문에 「이 결정은 사람 계정으로 PR #N 에 그대로 올라간다」가 적힌 창에서
   고른 보기가 `- <머리말>: <보기>` 줄이 되어 사람 계정으로 올라간다. 세션은 그 글을 쓰지 않는다 — 창 기록
   훅(`window_record.sh`)이 고른 보기를 기록하고 `human_comment.sh` 가 그 기록만 올린다. 창에서 고른 것이 게시
   동의라서, 설치되는 `settings.json` 이 레포 루트에서 입력한 그 명령을 허용해 권한 프롬프트가 없다. 세션이 도중에
   들어간 worktree 에서 올릴 때는 그 worktree 루트에서의 경로로 불러 allow 와 모양이 달라 권한 검사를 거친다 —
   default 모드에서는 권한 프롬프트가 한 번 표시되고 auto 모드에서는 분류기가 정한다. 보기 대신 직접 쓴 말 ·
   보기에 단 메모 · 창에 쓴 글이 있는 질문과 답을 비운 질문은 그대로 올라가지 않는다 — 세션이 같은
   머리말의 창으로 다시 묻고, 직접 쓴 것이 있던 질문은 결정이 담긴 구간이나 요지를 보기로 만든다. 자리를 비워
   저절로 닫힌 창은 기록되지 않는다.
2. PR 웹에서 직접 코멘트를 쓴다. 「N라운드 코멘트」 창에서 「PR 웹에 쓴다」를 고르고, 다 쓴 뒤 세션의 「PR 웹
   코멘트」 창에서 「PR 웹에 썼다」를 고른다. 세션은 라운드 코멘트 뒤의 사람 계정 코멘트를 결정으로 읽는다.

**머지 승인은 Approve 다.** PR 작성자가 봇이라 사람이 그 PR 을 Approve 할 수 있다. `merge-pr` 은 결정
코멘트를 올리고 GitHub auto-merge 를 켠 뒤, 응답을 Approve 요청 블록과 「PR #N 최종 검토」 창으로 끝낸다.
사람은 Approve 하고 창에서 「Approve 했다」를 고른다. Approve 가 달리면 GitHub 이 머지하고, 세션은 사람이 창에서
고른 뒤 머지됐는지 한 번 보고, 로컬 브랜치를 정리한 뒤 「다음 일」 창으로 묻는다. auto-merge 를 켤 수 없는 레포(승인을 요구하지 않거나
auto-merge 를 허용하지 않은 레포)에서는 창에서 고른 뒤 세션이 지금 head 에 쓰기 권한이 있는 사람 계정의
Approve 가 있는지 확인해 머지한다.

**「다음 일」 보기는 그때마다 열린 이슈 전체에서 고른다.** 세션은 머지 뒤와 일 하나가 끝났을 때, 새 세션이 할 일을
고를 때 열린 이슈 · 열린 PR · 다른 worktree 를 다시 받아(`.claude/hooks/backlog.sh`) 지금 깨져 있는 것부터 순서를
정하고, 창 앞 응답에 상위 후보와 그 이유, 다른 세션이 맡아 뺀 이슈를 적는다. 보기에 없는 후보도 응답에 있으니 그중에서
고를 수 있다. 고르는 법은 `merge-pr` 의 「다음 일」 문단에 있다.

| 시점 | 무엇 | 막나 |
|---|---|---|
| 세션 시작 | 설치 토큰을 받아 세션의 gh 를 봇 계정에 연결한다(`bot_session.sh`) | 못 받으면 까닭을 세션에 알린다. 쓰기는 아래 줄이 막는다 |
| gh 명령 · git 원격 명령마다 | gh 와 git 의 계정 · 자격 증명을 바꾸는 것(환경을 비우는 `env -i` 포함), `gh auth` 명령(`status` 도 봇 토큰을 출력한다), 토큰을 출력하는 `git credential` 과 봇 디렉터리를 가리키는 명령(토큰이 없는 `expires` · `session-env` · `wired` 는 뺀다. Read · Write · Edit 도구는 설치되는 `settings.json` 의 `deny` 가 막는다), 연결되지 않은 세션이 gh 로 쓰거나 `git push` 하는 것, 연결된 세션이 github.com 의 SSH 주소로 푸시하는 것. 명령 치환(`$(…)` · 백틱) 안도 본다(`bot_guard.sh`). 토큰이 끝나 가면 새로 받는다 — 안에서 gh 를 부르는 스크립트(`human_review.sh` · `backlog.sh`) 앞에서도 | 막는다. gh 의 읽기 명령과 `git fetch` · `pull` 은 막지 않는다 |
| Bash 명령마다 | App 개인키를 가리킬 수 있는 명령. 명령 글자에 `.config/<App 이름>` 이나 `<App 이름>/key.pem` 이 들었거나 `.config` 와 `key.pem` 이 함께 든 명령이다(`bot_guard.sh`, 6절 2) | 막는다. 거절 사유가 해당한 글자와, 키는 사람이 터미널에서 다룬다는 것을 알린다 |
| 질문 창이 끝날 때 | 질문에 「이 결정은 사람 계정으로 PR #N 에 그대로 올라간다」가 적힌 창에서 사람이 고른 보기를 봇 디렉터리에 기록한다(`window_record.sh`). 직접 쓴 말 · 메모 · 창에 쓴 글이 있는 질문과 답을 비운 질문은 줄로 적지 않고, 저절로 닫힌 창과 질문을 더 요청한 창은 기록하지 않는다. 세션이 봇 디렉터리를 쓰는 것은 설치되는 `settings.json` 의 `deny` 와 `bot_guard.sh` 가, 봇 설정이 있는 레포 안에서 이 훅을 직접 실행하는 것은 `bot_guard.sh` 가 막는다 | 기록만 한다 |
| 사람 계정으로 올릴 때 | `human_comment.sh <PR 번호>` 는 창 기록만 올린다. 한 줄 정규형이 아니거나, 스크립트 경로가 훅 디렉터리 밖을 가리키거나(하위 디렉터리에서 레포 루트 기준 경로를 입력한 경우도 그렇다 — 경로를 cwd 기준으로 푼다), 셸의 `-c` 인자 안에 두었으면 막는다(`bot_guard.sh`) | 창에서 고른 것만 올라간다 |
| 리뷰 에이전트가 보고할 때 | 에이전트 종류가 `cold-reviewer` 인 에이전트의 보고를 봇 디렉터리에 `리뷰한 head:` 별로 기록한다(`review_record.sh`). 마지막 줄이 `**Verdict**:` 가 아닌 보고는 한 번 되돌린다. 세션이 이 훅을 직접 실행하는 것은 `bot_guard.sh` 가 막는다 | 기록한다. 마지막 줄이 Verdict 가 아닌 보고는 한 번 되돌린다 |
| 라운드 코멘트 게시 | `(사람)` 인용이 사람 계정 코멘트의 불릿 하나나 줄 하나에 글자 그대로 있는지(`round_comment_quotes.sh`), 「콜드 리뷰 전문」이 그 head 의 콜드 리뷰 기록과 글자로 같은지(`round_comment_cold.sh`). 기록은 `cold_review.sh <head>` 로 꺼낸다 | 막는다 |
| auto-merge 를 켤 때 | 승인이 모자라 막힌 PR(`reviewDecision` `REVIEW_REQUIRED` · `mergeStateStatus` `BLOCKED`)에서만 켜는지 — gh 는 바로 머지할 수 있는 PR 에서 `--auto` 를 무시하고 그 자리에서 머지한다. auto-merge 가 켜진 PR 의 브랜치로 가는 푸시도 막는다(`bot_guard.sh`) | 막는다. 머지는 브랜치 보호가 요구하는 Approve 가 달릴 때 GitHub 이 한다. 조회가 멈춰 막았으면 거절 사유가 멈춘 명령을 알린다 |
| auto-merge 를 켤 수 없을 때의 머지 전 | 지금 head 에 사람 계정의 Approve 가 있는지(`merge-pr` 2절) | 멈춘다. 브랜치 보호가 승인을 요구하면(3절) GitHub 도 막는다 |

`(사람)` 인용의 원본은 글쓴이의 레포 권한이 write 이상이고(봇 계정은 권한 조회에서 빠진다), 글쓴이가 아닌 계정이
마지막으로 고치지 않은 코멘트다. Quote reply 로 넣은 `>` 줄은 남의 글이라 원본이 아니다. 무엇을 원본으로 고르고 어떤 Approve 를
인정하는지는 `.claude/hooks/human_review.sh` 머리에 있다.

**켜는 법.** 한 번 한다.

1. GitHub App 을 만든다. 권한은 Contents · Issues · Pull requests · Workflows 쓰기와 Checks ·
   Actions 읽기다(Metadata 읽기는 기본으로 들어 있다). Contents 쓰기는 푸시와 머지에, Workflows 쓰기는
   `.github/workflows` 를 바꾼 커밋을 푸시하는 데, Issues · Pull requests 쓰기는 이슈 · PR · 코멘트에,
   읽기 둘은 CI 결과와 CI 로그를 읽는 데 쓴다. 세션의 GitHub 행동은 모두 봇 한 계정으로 한다 — 세션 시작 훅이
   세션 환경에서 git 이 github.com 자격 증명을 gh(봇)에게서만 받고 github.com 의 SSH 주소
   (`git@github.com:` · `ssh://git@github.com/`)도 https 로 바꿔 쓰게 하므로, 푸시도 봇 토큰을 쓴다.
   사용자의 git 설정 파일은 바꾸지 않는다.
2. App 의 개인키를 만들어 `~/.config/<App 이름>/key.pem` 에 둔다(권한 600). 커밋하지 않는다. 키를 두고
   확인하는 일은 사람이 터미널에서 한다. 세션이 이 자리를 읽는 명령은 막힌다 — 설치되는 `settings.json` 의 deny
   `Read(~/.config/*/key.pem)` 이 Read 도구와 `cat` 같은 파일 명령을, 막기 훅이 `.config/<App 이름>` 이나
   `<App 이름>/key.pem` 이 든 명령과 `.config` · `key.pem` 이 함께 든 명령을 막는다. 둘 다 이름이 적힌 경로로 알아보므로
   디렉터리 단위로 읽는 명령(`grep -r … ~/.config`)과 스크립트 파일 안의 경로는 막지 못한다(아래 「무엇을 못
   막나」). 토큰은 `bot_token.sh` 가 받는다.
3. App 을 설치하고 저장소 범위를 「Only select repositories」로 두어 킷을 쓰는 레포만 고른다.
   개인키나 토큰이 새면 설치 범위 안의 레포에 브랜치를 푸시하고 PR 을 열 수 있고, 브랜치 보호가 승인
   리뷰를 요구하지 않으면 CI 의 검사가 모두 통과한 PR 을 머지할 수 있다. Workflows 쓰기로 그 CI 자체도 바꿀 수 있다.
4. `.claude/bot.json` 을 커밋한다: `{"app_id": <App ID>, "app": "<App 이름>"}`. App 이름은 App
   페이지 URL(`github.com/apps/<App 이름>`)의 이름이고, 봇 계정은 `<App 이름>[bot]` 이다. App 이름을
   `kit-bot` 으로 짓지 않는다 — 막기 훅이 명령 글자의 그 이름을 봇 디렉터리(`<git 공통 디렉터리>/kit-bot/`)로
   읽어, App 이름이 든 명령(봇 계정의 PR 을 거르는 `gh pr list --author kit-bot[bot]` 등)을 막는다.
5. 세션을 다시 시작한다. 연결하지 못하면 그 까닭이 세션에 전달된다. 직접 보려면 레포에서
   `bash .claude/hooks/bot_token.sh` 를 실행한다 — 성공하면 봇 디렉터리의 경로를, 실패하면 까닭을
   출력한다.
6. 킷의 `install.sh <이 레포 경로> --protect` 를 다시 실행한다. 봇 설정이 있으면 브랜치 보호가 사람의
   Approve 하나를 요구하고, 새 커밋이 오면 이전 승인을 없던 것으로 하고, 마지막 푸시는 푸시한 사람이
   아닌 사람이 승인하게 한다. 레포 설정 「Allow auto-merge」 · 「Automatically delete head branches」도 켜서,
   Approve 가 달리면 GitHub 이 머지하고 head 브랜치를 지운다. 봇이 푸시하므로 그 승인은 사람의 것이다. 사람이 PR 브랜치에 직접 푸시하면
   그 사람의 Approve 는 브랜치 보호가 세지 않는다 — 세션이 다시 푸시한 뒤에 Approve 한다. PR 웹의 「Update branch」
   버튼이 누른 사람의 푸시로 세어지는지는 확인하지 않았다.

**새 레포에서 쓸 때.** 권한은 App 에 한 번 정하는 것이라 레포마다 다시 주지 않는다. 할 일은 둘이다 —
App 설치의 저장소 목록에 그 레포를 더하고, 그 레포에 `.claude/bot.json` 을 커밋한다. 목록에 없으면
세션을 시작할 때 「App 설치에 이 레포가 없다」가 나온다.

**세션의 git 이 닿는 곳.** 세션에서 github.com 에 접속하는 git 명령은 origin 만이 아니라 모두(서브모듈 ·
git 의존성 포함) 봇 토큰을 쓴다. 그래서 설치 범위 밖의 비공개 레포는 사람의 터미널에서는 받아지지만 세션에서는
fetch · clone 이 안 된다. 세션에서 써야 하면 그 레포도 App 설치의 저장소 목록에 더한다.
사람의 git 설정이 github.com 의 https 를 SSH 로 바꾸면(`url."git@github.com:".insteadOf` ·
`pushInsteadOf`) 세션의 푸시에 SSH 키, 곧 사람 계정이 쓰이므로 막기 훅이 그 푸시를 막는다. 이 레포에서만
그 규칙을 끄려면 소유자까지 적은 더 긴 규칙을 둔다 — git 은 맞는 규칙 가운데 가장 긴 것을 쓴다:

```bash
git config --local url."https://github.com/<소유자>/".insteadOf "https://github.com/<소유자>/"
git config --local url."https://github.com/<소유자>/".pushInsteadOf "https://github.com/<소유자>/"
```

**App 권한을 바꾸면 설치에서 한 번 더 승인한다.** App 설정에서 권한을 더해도, 설치 설정 페이지에서
새 권한을 승인하기 전에는 설치 토큰이 옛 권한이다.

**팀.** `.claude/bot.json` 은 커밋되므로 이 레포를 clone 한 사람 모두에게 적용된다. 세션을 쓰는
사람마다 그 App 의 개인키가 있어야 한다(App 하나에 개인키를 25개까지 만든다). 개인키가 없는 사람의
세션은 봇 계정에 연결되지 않아, gh 의 읽기 명령과 `git fetch` · `pull` 만 되고 gh 로 쓰거나 푸시하지
못한다. 이미 실행 중인 세션도 작업 트리에 `.claude/bot.json` 이 들어오면(그 커밋이 있는 브랜치로 옮기거나
합칠 때) 연결되지 않은 세션이 되므로 다시 시작해야 한다. 두 리뷰와 `merge-pr` 은 라운드 코멘트 뒤의 사람
계정(OWNER · MEMBER · COLLABORATOR) 코멘트를 결정으로 읽는다. MEMBER 는 레포 권한과 상관없이 조직
구성원이면 붙으므로, `(사람)` 인용의 원본과 Approve 는 쓰기 권한이 있는 사람의 것만 센다. 리뷰하는 사람이
여럿이면 필요 승인 수를 GitHub 의 브랜치 보호 설정에서 올린다(`--protect` 는 하나로 둔다). `merge-pr` 은
GitHub 이 그 수로 계산한 판정(`reviewDecision`)까지 본다.

**무엇을 못 막나.** gh 명령 막기는 명령 글자로 알아본다. 스크립트 파일이나 인라인 인터프리터 안의
호출(그 안의 `git push` 포함)은 못 보고, 명령 글자에 `GH_TOKEN` 같은 낱말이 있으면 검색이나 커밋 메시지도 막는다(그 글자는
파일로 옮겨 전달한다). 그래서 세션이 봇 연결을 지우는 스크립트를 새로 써서 실행하면 사람 계정으로 올라간다. App 개인키도
같다 — 스크립트 파일 안의 경로와, `key.pem` 을 적지 않고 디렉터리 단위로 읽는 명령(`grep -r PRIVATE ~/.config`)은
deny 규칙도 막기 훅도 막지 못한다. SSH 설정의 호스트 별칭으로 적은 원격(`git@github-me:me/r.git`)은 github.com 인지
알 수 없어 그 푸시를 막지 못한다 — 그 푸시에는 SSH 키, 곧 사람 계정이 쓰인다. origin 이 별칭이면 세션이
봇 계정에 연결되지 않아 푸시가 막히므로, origin 이 아닌 원격에 별칭을 쓴 레포에서만 생긴다. 형식대로
입력한 명령의 실수를 막는 것이고, 작정한 우회는 CI 와 브랜치 보호의 몫이다. 권한 프롬프트의 허락은
사람이 그 글을 읽었다는 것까지 보여 주지 않는다.

막기 훅의 `timeout`(`.claude/settings.json`, 기본값 90초)을 `BUDGET`(`bot_guard.sh`, 기본값 60초) 이하로 줄이면,
조회가 멈췄을 때 Claude Code 가 막기 훅을 먼저 끝내 푸시가 검사 없이 실행된다.
