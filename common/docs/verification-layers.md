# 검증 계층

같은 결함을 세 계층이 중복해서 보지 않는다. **아래 계층이 잡을 수 있으면 위 계층에서 뺀다.**
이것이 품질을 올리면서 동시에 리뷰 시간을 줄이는 유일한 수다.

| 계층 | 잡는 것 | 성질 | 비용 |
|---|---|---|---|
| **L1 기계** — 타입·린터·테스트·스캐너 | 결정론적으로 판정 가능한 것 | 100% 재현. 놓치지 않음. | 1회 설정, 이후 0 |
| **L2 AI 리뷰** | 의도·설계 정합·누락된 케이스 | 확률적. **자기 코드에 특히 약함.** | 매 PR |
| **L3 사람** | 제품 판단·시각·실사용 흐름·트레이드오프 | 대체 불가 | 비쌈. 아껴 쓴다. |

---

## L1로 내려야 하는데 L2에 남아있기 쉬운 것들

리뷰 체크리스트에 아래가 **문장으로** 적혀 있으면, 그건 린터 설정이 빠졌다는 뜻이다.

| 리뷰 체크리스트에 흔히 적히는 문장 | 실제 집행자 |
|---|---|
| "에러를 `%w`로 래핑했나" | `errorlint` |
| "response body·rows·파일을 닫았나" | `bodyclose` · `sqlclosecheck` · `rowserrcheck` |
| "context를 전파·취소하나" | `contextcheck` · `noctx` |
| "시크릿이 코드·로그에 없나" | `gosec` · `gitleaks` |
| "루프 변수 캡처 문제 없나" | `copyloopvar` |
| "에러를 삼키지 않나" | `errcheck` · `nilerr` |
| "접근성 속성이 있나" | `jsx-a11y` |
| "`any`를 쓰지 않았나" | `@typescript-eslint/no-explicit-any` |
| "프론트가 절대 URL을 쓰지 않나" | `no-restricted-syntax` (프로젝트 하드룰 코드화) |
| "금지한 라이브러리를 안 썼나" | `no-restricted-imports` · `depguard` |

> **프로젝트 하드룰은 산문이 아니라 린트 규칙으로 쓴다.** 산문 규칙은 AI가 읽고
> 지키려 "노력"하지만, 린트 규칙은 지켜지지 않으면 빌드가 깨진다.

## L2가 실제로 필요한 것 (기계가 못 잡음)

- 이 diff가 **한 가지 일**을 하는가
- 테스트가 *의미 있는* 케이스를 덮는가 — 커버리지 %는 L1, **케이스 선택**은 L2
- **PR 본문의 주장이 diff와 맞는가** (산출물 규칙 R3)
- **SPEC의 요구가 구현에 실제로 도달했는가** (추적표 대조)
- 에러 분류가 맞는가 (재시도 가능 / 불가)
- 이 추상화가 지금 필요한가, 아니면 투기적 seam인가

## L2를 두 번 돌리는 조건 — 콜드 리뷰어

자기 코드를 자기 컨텍스트로 보는 리뷰는 자기 가정을 재확인하기 쉽다.
그래서 **콜드 컨텍스트 리뷰어**(diff + 규칙 + SPEC만 보고 시작하는 별도 에이전트)를
2차로 돌린다.

**기본은 "돈다" 다.** 건너뛰는 경우는 하나뿐이다:

- [ ] **글만 바뀐 PR** — README·ADR·dev-log 같은 산문. 사람이 읽을 글만 바뀌었을 때.

> **설정·CI 워크플로·훅·게이트 스크립트·템플릿은 "글"이 아니다 — 돈다.**
> 확장자로 판단하지 마라. `.json`·`.yml`·`.md` 여도 그것이 *동작을 규정*하면 코드다.
> 되돌릴 수 없는 실수는 바로 거기에 산다.

판단이 애매하면 아래 축에 걸리는지 본다. 하나라도 걸리면 **반드시** 돈다:

돈이 나가는 경로 · 동시성/트랜잭션/락 · 인증/시크릿/권한 ·
DB 스키마/마이그레이션 · 배포 절차 · **게이트·훅·CI 자체**

### 두 층을 다 돌린다 — 서로 다른 것을 잡는다

| 층 | 잡는 것 | 그쪽만 가능한 이유 |
| --- | --- | --- |
| 셀프(맥락 보유) | 결정과 어긋난 구현 · **낡은 주장**(PR 본문이 최신 커밋을 안 담음) | 무엇이 언제 정해지고 바뀌었는지 아는 쪽만 안다 |
| 콜드(맥락 없음) | 작성자가 "맞다고 아는" 가정 · diff 밖 파급 | 작성자의 설명으로 안심할 수 없다 |

> 실측: 첫 두 번의 실전에서 셀프 3건 vs 콜드 11건, 셀프 3건 vs 콜드 7건.
> 콜드가 크게 앞섰지만 **셀프만 잡은 것도 있었다** — "PR 본문이 5개 커밋만큼 낡았다"는
> 맥락을 가진 쪽만 알 수 있다. 한 층으로 줄이지 마라.
>
> 처음에는 다섯 개 위험 축에만 걸었는데, 그 문구가 하필 **설정·CI·훅 변경을 좁게**
> 읽히게 만들었다 — 되돌릴 수 없는 실수가 실제로 사는 곳이다. 기본값을 "돈다"로 뒤집었다.

## L3(사람)에게 남기는 것 — 명시적으로

- 시각 · 레이아웃 · 모션 · 색의 실제 지각
- 여러 화면을 오가는 실사용 흐름
- 제품 판단 (이 기능이 맞나, 이 문구가 맞나)

> 측정값 통과와 실제 지각은 **다른 평가축**이다. 대비비 기준을 통과하고도
> 다크 배경에서 안 보일 수 있고, 단위 테스트가 개별 동작을 다 덮고도
> 화면을 오가는 흐름에서 깨질 수 있다.

산출물 규칙 R6에 따라, **자동화가 닿지 않는 이 범위를 문서에 적는다.**
적지 않으면 검증이 조용히 사라지고 아무도 사라진 줄 모른다.

## 강제는 에이전트 밖에 둔다 (핵심)

에이전트 훅(`.claude/settings.json` · `.codex/hooks.json`)은 **그 에이전트가
그 도구를 통해 행동할 때만** 작동한다. 사람이 터미널에서 직접 하거나,
다른 에이전트로 갈아타면 강제가 통째로 사라진다.

| 두는 곳 | 누구에게 걸리나 | 우회 |
|---|---|---|
| 에이전트 훅 | 그 에이전트, 그 도구를 쓸 때만 | 도구를 바꾸면 사라짐 |
| **git hooks** | 그 레포에서 커밋·푸시하는 **모두** (사람 포함) | `--no-verify` · 활성화 안 한 clone |
| **CI** | 원격에 올라온 **모든** 변경 | 없음(머지는 가능) |
| **브랜치 보호** | 우회 불가 | 없음 |

### git hooks 의 정직한 한계

훅 파일은 `.ai-kit/git-hooks/` 에 커밋되므로 clone 을 따라온다. 그러나 이를 활성화하는
`core.hooksPath` 는 **로컬 설정이라 clone 되지 않는다** — git 이 보안상 의도한 동작이고
우회 방법이 없다. 새로 clone 한 사람은 한 줄이 필요하다:

```bash
git config core.hooksPath .ai-kit/git-hooks
```

그리고 `git commit --no-verify` 로도 넘어간다.

세 번째 한계는 더 조용하다. **훅 파일이 실행권한 없이 커밋돼 있으면 git 은 그것을
건너뛴다** — `hint:` 한 줄이 stderr 로 나갈 뿐 커밋은 성공한다.

```
$ git commit -m ...
hint: The '.ai-kit/git-hooks/pre-commit' hook was ignored because it's not set as executable.
[main abc1234] ...        ← 훅이 exit 1 인데도 커밋됨
```

설치가 잘못될 걱정은 아니다(`cp -R` 이 킷의 100755 를 그대로 옮긴다). **설치 이후**에
모드가 떨어지는 경로가 실재한다 — 둘 다 재현했다:

| 방아쇠 | 결과 |
|---|---|
| `core.fileMode=false` 인 레포 | 작업트리는 755 인데 **커밋된 모드는 100644** |
| 훅을 편집기가 지우고 다시 쓸 때 | 인덱스 모드가 **100644** 로 바뀜 |

훅은 `.ai-kit/` 에 vendor 돼 레포 안에 있으니 누군가 손대는 것을 전제한 파일이다.
그런데 손대는 순간 강제가 조용히 꺼질 수 있고, 로컬에서는 아무도 눈치채지 못한다.

파일이 *있는지*만 보는 검사는 이것을 통과시킨다. 그래서 CI 가 커밋된 모드까지 본다
(`[ -x ]`). 게이트 스크립트는 훅이 `bash <경로>` 로 부르므로 권한이 필요 없다 —
거기까지 요구하면 멀쩡한 레포에서 오탐이 난다.

> **그래서 로컬 훅은 강제가 아니라 조기 피드백이다.** 되돌릴 수 없는 결과를 막는
> 진짜 강제는 CI + 브랜치 보호뿐이다. 훅을 믿고 CI 를 생략하면 강제가 0 이 된다.

> 규칙: **되돌릴 수 없는 결과를 막는 강제는 git hooks·CI·브랜치 보호에 둔다.**
> 에이전트 훅은 *편의*(자동 포맷·조기 피드백)에만 쓴다.

### 왜 에이전트 `pre_push` 훅을 두지 않는가

킷은 이 훅을 처음부터 두지 않았고, 프로젝트에서도 킷 도입 때 지웠다. 근거를 남긴다 —
**제거한 구성요소의 이유를 안 적는 것이 R4·R5 위반**이고, 안 적으면 다음 사람이
"빠졌네" 하고 되살린다.

이유는 셋이고 전부 확인했다:

1. **중복이다.** git `pre-push` 훅이 이미 **모든** push 에서 게이트를 돌린다
   (`common/git-hooks/pre-push` 가 `gate.sh --base` 를 호출한다). 에이전트 훅을 더하면
   같은 검사가 두 번 돈다.
2. **비싸다.** 게이트는 실 모노레포에서 한 번에 수십 초다. 두 번이면 그만큼 두 배다.
3. **얻는 게 없다.** 에이전트 훅을 두는 유일한 이유는 "에이전트가 결과를 보게" 인데,
   **git 훅의 stderr 는 그대로 에이전트에게 전달된다.** 실측:

   ```
   $ git commit -m x
   훅이 남긴 메시지 (stderr)      ← 에이전트가 받는 출력에 그대로 들어온다
   ```

> 게다가 에이전트 훅은 그 에이전트가 그 도구를 쓸 때만 걸린다(원칙 1). 사람이 손으로
> push 하면 사라진다. **없어도 되는 층이면서 신뢰할 수도 없는 층**이라 두지 않는다.
