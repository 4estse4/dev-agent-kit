## 이 문서를 쓰는 규칙

1. **규칙마다 집행자를 표시한다** — `[hook]` `[lint]` `[CI]` `[test]` `[review]` `[사람]`
2. **집행자가 `[review]`·`[사람]` 뿐인 규칙은 지켜지지 않는다고 가정한다.**
   불편하면 집행자를 기계로 바꿔라(린트 규칙·테스트·CI 검사).
3. **적용 대상이 없는 규칙은 지운다.** 존재하지 않는 코드를 규율하는 규칙은
   규칙 목록 전체의 신뢰도를 깎는다.
4. 길이 상한을 정하고 지킨다(권장 150줄). 넘으면 무언가를 지울 때다.

## 작업 루프

feature 브랜치 → 구현 → 테스트 → `commit` → `open-pr` → `review-diff` → 수정 → 머지.

- 파일 3개 이상 또는 구조에 영향 주는 변경은 **먼저 계획을 제시하고 승인받는다.**
- 외부 API·SDK 는 **기억으로 짜지 않는다.** 공식 문서나 실호출로 확인한다. `[review]`
  → 확인한 근거(문서 URL·실행 결과)를 코드 주석이나 ADR 에 남긴다.
- 읽지 않은 파일의 내용을 단정하지 않는다. 먼저 읽는다.
- 머지 전 검토에서 나온 수정은 **diff 제시 → 확인 → 커밋** 순서. 푸시 먼저 하지 않는다.

## 서브에이전트 사용 정책

서브에이전트(Task/Agent 도구)를 쓸 만한 작업은 먼저 분류한다. `[review]`

1. **명백히 인라인** — 좁은 locate-then-read, 필요한 맥락을 이미 갖고 있고,
   답을 찾는 것이 넓은 탐색이 아님 → 묻지 말고 그대로 진행한다.
2. **명백히 서브에이전트** — 결론만 필요한 넓은 fan-out 탐색이거나, 그대로 두면
   메인 컨텍스트를 크게 잡아먹는 격리 작업 → 띄우고, 끝나면 한 줄로 보고한다
   (에이전트 종류 · 왜 · 무엇이 나왔나).
3. **진짜 애매** — 큰 작업이지만 판단하려면 원자료를 내 컨텍스트에 둬야 할 수도 있거나,
   비용/이득이 비슷함 → **띄우지 말고** (a) 추천(서브에이전트 vs 인라인) (b) 한 문장 이유
   (c) 비용 트레이드오프(추가 컨텍스트 + 콜드 스타트 재독 vs 메인 절약)를 말하고 기다린다.

> 판단 기준은 항상 둘이다: **원자료가 내 컨텍스트에 필요한가**, 그리고
> **답을 찾는 것이 넓은 탐색인가.** 둘이 같은 방향이면 행동하고(1 또는 2),
> 어긋나면 묻는다(3).

## 산출물 언어

규약이 없으면 산출물마다 언어가 흔들린다. 아래를 따른다.

| 산출물 | 언어 | 왜 |
| --- | --- | --- |
| 코드 주석 · 식별자 | **영어** | 코드가 가장 오래 살고 가장 널리 읽힌다 |
| 커밋 메시지 · PR 제목 | **영어** | 도구·grep·업계 관행 |
| 브랜치명 · 태그 | **영어(ASCII)** | URL·CLI 에서 비ASCII 는 깨진다 |
| **CI 워크플로(잡·스텝 이름)** | **영어(ASCII)** | 잡 이름은 브랜치 보호 required check 이름으로 쓰인다. 스텝 이름은 로그에서 영어 도구 출력과 섞이므로 함께 맞춘다 |
| PR 본문 · 리뷰 코멘트 | 팀 언어 | 정밀한 판단이 오가는 곳 — 가장 정확히 쓸 수 있는 언어로 |
| 설계 문서(SPEC·ADR·plan·dev-log) | 팀 언어 | 위와 같음 |
| README · RUNBOOK | 팀 언어 | 읽는 사람 기준 |
| 이 파일 · 스킬 · 에이전트 정의 | 팀 언어 + 영어 기술용어 | 아래 |
| 훅·스크립트의 사람용 메시지 | 팀 언어 | 읽는 사람이 운영자 |

**기술용어는 번역하지 않는다.** `%w` · `errors.Is` · `FOR UPDATE SKIP LOCKED` ·
`idempotency` 는 원어로 둔다 — 번역하면 오히려 모호해진다.

### 커밋 트레일러

커밋 메시지에 붙이는 트레일러는 이 한 줄뿐이다. `[review]`

```
Co-Authored-By: Claude Opus 5 (xhigh) <noreply@anthropic.com>
```

모델명과 effort 를 괄호로 함께 적는다. 세션 URL(`Claude-Session:`)은 붙이지 않는다 —
남이 열 수 없어 히스토리에 값을 못 한다.

**커밋 시점의 실제 값을 쓴다.** `/model` · `/effort` 로 세션 중간에 바뀌므로 기억으로
쓰지 마라. 상태줄에 그대로 떠 있다.

> 왜 커밋마다 적나 — 비대칭이다. 기록 비용은 커밋당 ~20자인데 **미기록 비용은 영구
> 복구 불가**다. "모델이나 effort 를 바꿔 결과를 비교해보자" 는 시점이 오면 이전 커밋의
> 귀속은 이미 사라졌고, 머지된 히스토리에는 소급할 수 없다. 이 킷의 논지가
> "AI 협업을 데이터로 말한다" 인데, 커밋 단위 귀속이 바로 그 데이터다.
>
> 별도 트레일러 키로 나누지 않고 한 줄에 담는 이유: `Co-Authored-By` 는 git·GitHub 이
> `이름 <이메일>` 로 파싱하는 표준 트레일러다. 괄호는 이름의 일부가 아니라 한정어로
> 읽히고, 집계도 된다:
>
> ```
> git log --format='%(trailers:key=Co-Authored-By,valueonly)' | sed -n 's/.*(\([^)]*\)).*/\1/p'
> ```

> 에이전트에게 주는 지시(이 파일·스킬)의 언어는 성능보다 **정밀도**가 기준이다.
> 어설픈 영어 규칙보다 정확한 팀 언어 규칙이 낫다. 진짜 리스크는 언어가 아니라
> **길이와 모호함**이다 — 이 파일의 150줄 상한이 언어 선택보다 중요하다.
