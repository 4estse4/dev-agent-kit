# CLAUDE.md — <프로젝트명>

> **이 프로젝트 규칙의 단일 출처.** 규칙을 다른 파일에 중복해 적지 않는다 —
> 두 벌이 되면 반드시 어긋나고, 어느 쪽이 진짜인지 아무도 모르게 된다.
> 처음이면 [`docs/process/kit-guide.md`](docs/process/kit-guide.md) 를 먼저 읽어라.

## 이 문서를 쓰는 규칙

1. **규칙마다 집행자를 표시한다** — `[hook]` `[lint]` `[CI]` `[test]` `[review]` `[human]`
2. **집행자가 `[review]`·`[human]` 뿐인 규칙은 지켜지지 않는다고 가정한다.**
3. **적용 대상이 없는 규칙은 지운다.** 존재하지 않는 코드를 규율하는 규칙은
   규칙 목록 전체의 신뢰도를 깎는다.
4. **일반론이 프로젝트 내용보다 길면 잘라라.** 근거 설명은 킷에 있다.

## 작업 루프

feature 브랜치 → 구현 → 테스트 → `commit` → `open-pr` → 리뷰 한 라운드 → 수정 → 머지.

- 파일 3개 이상 또는 구조에 영향 주는 변경은 **먼저 계획을 제시하고 승인받는다.**
- **리뷰는 한 라운드를 돌고 멈춘다.** 두 층의 결과를 하나의 코멘트로 올린 뒤 사람에게
  보고하고, **다음 라운드를 돌지·머지할지는 사람이 정한다.** 라운드 수에 상한은 없다 —
  진짜로 고칠 것이 나오면 여러 번 돌아도 된다. 정하는 것이 사람이면 된다. `[human]`
  (`settings.json` 의 `ask` 가 게시와 콜드 스폰에서 프롬프트를 띄운다 — 그 층은
  횟수를 제한하지 않고 매번 사람 눈에 띄게 할 뿐이다)
- **머지는 사람이 지시했을 때만 한다.** 두 층이 `Approve` 를 냈다는 것은 그 층들의
  의견이지 허락이 아니다. `[human]`
- 외부 API·SDK 는 **기억으로 짜지 않는다.** 공식 문서나 실호출로 확인한다. `[review]`
  → 확인한 근거(문서 URL·실행 결과)를 코드 주석이나 ADR 에 남긴다.
- 읽지 않은 파일의 내용을 단정하지 않는다. 먼저 읽는다.
- 머지 전 검토에서 나온 수정은 **diff 제시 → 확인 → 커밋** 순서. 푸시 먼저 하지 않는다.


## 산출물 언어

| 산출물 | 언어 |
| --- | --- |
| 코드 주석 · 식별자 · 커밋 메시지 · PR 제목 · 브랜치명 | **영어** |
| **CI 워크플로(잡·스텝 이름)** | **영어(ASCII)** — 잡 이름이 required check 이름이 된다 |
| PR 본문 · 리뷰 코멘트 · 설계 문서 · README · RUNBOOK | 팀 언어 |
| 이 파일 · 스킬 · 에이전트 정의 · 훅의 사람용 메시지 | 팀 언어 + 영어 기술용어 |

**기술용어는 번역하지 않는다.** `errors.Is` · `idempotency` 는 원어로 둔다.

### 커밋 트레일러

커밋 메시지에 붙이는 트레일러는 이 한 줄뿐이다. `[review]`

```
Co-Authored-By: Claude Opus 5 (xhigh) <noreply@anthropic.com>
```

**커밋 시점의 실제 모델·effort 를 쓴다** — 세션 중간에 바뀌므로 기억으로 쓰지 마라.
상태줄에 떠 있다. 세션 URL(`Claude-Session:`)은 붙이지 않는다.


## 산출물

설계 근거는 `docs/process/artifact-rules.md`(킷이 함께 설치한다). 요약:

- 검증 산출물은 **발견만** 쓴다. "문제없음"의 근거를 서술하지 않는다.
- "테스트 통과함" 같은 **주장 대신 명령 출력(증거)** 을 붙인다.
- AI 가 쓴 산출물은 다음 단계에서 **대조 대상**이지 배경이 아니다.

| --- | --- |
| 실행 | |
| 테스트 | |

> 아니라 "검사되지 않았다" 이고, 로컬만 관대하면 로컬에서 통과한 것이 CI 에서 실패해
> 공용 자원과 사람 시간을 왕복에 쓴다. 불가피할 때만 `AI_KIT_ALLOW_MISSING_TOOLS=1` 로
> 내리고, 그때 무엇이 검사되지 않는지 출력된다.
